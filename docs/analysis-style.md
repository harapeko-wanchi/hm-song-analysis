# 楽曲分析（analysis/<id>.md）の書き方

音楽ジャーナリストのレビュー、または音楽誌の楽曲分析記事として読める文章にそろえる。
詳細ページ（`song.html?id=<id>`）では本文をそのまま記事として表示し、9軸スコア・ポジションマップ・似ている曲はページ側で別に表示する。

## 構成

```
# <曲名> — 楽曲分析

<リード文>

## 基本情報

| 項目 | 値 |
|------|-----|
| リリース | YYYY-MM-DD |
| 作詞 | … |
| 作曲 | … |
| 編曲 | …（無ければ行ごと省く） |
| Key | … |
| BPM | … |
| 編成 | … |

## <論点の見出し>        ← 2〜4 本。曲のいちばんの聴きどころから順に
## 楽曲を追う            ← セクションごとのコード進行と解説
### Intro
### Aメロ（<歌い出しの数語>）
…
## カタログの中で        ← Hey!Mommy! の他の曲・同じ作曲家の曲との比較
## 総評                  ← 締めの 1〜2 段落
```

- 先頭の `# <曲名> — 楽曲分析` は残す（詳細ページでは自動で外れ、ページのタイトルが代わりに出る）。
- **リード文**は見出しを付けず、`#` の直後に 2〜3 文で書く。この曲を一言で言うと何か、どこを聴けばいいかを示す。
- **論点の見出し**は記事の小見出しとして、内容が分かる言い切りの句にする（例:「ドミナントを消した循環が描く堂々巡り」）。「特徴1」「コード面」のような分類名にしない。
- 「9軸スコア」「ポジションマップ」の数値セクションは書かない（ページ上部に出る）。スコアに触れるときは本文の中で「エモ 9.9 はカタログ最高値」のように必要な分だけ書く。

## 文体

- **だ・である調**。批評として言い切る。根拠のない推測は「〜と思われる」「〜と聴こえる」とする。
- **段落で書く**。箇条書きは、同じ種類のものを並べて見せたいときだけ（1 記事に数か所まで）。
- **表は「基本情報」と、比べることに意味がある比較表 1 つまで**。それ以外の表は文章にする。
- **太字は段落に 1〜2 か所まで**。いちばん伝えたい言葉だけに使う。
- 和声の用語（ディグリー、セカンダリードミナント、借用和音など）は使ってよいが、初出ではその響きや効果を言葉で添える。「V/vi（vi への二次ドミナント）」のように。
- 「★」「→」の連続、「=」での言い換えなどのメモ書き風の記法は使わない。

## コード進行と歌詞

- コード進行は ```` ``` ```` のコードブロックで示し、その直後の段落で解説する。
- コードブロックに歌詞を全行書き写さない。どの箇所かが分かるよう、行の頭に歌い出しの数語だけを添える（例: `C → Dm → Am → F    「呆れるほど…」`）。
- 本文で歌詞を引用するときは、論じるのに必要な短いフレーズに限る（`songs.json` の `lyrics_hooks` 程度の長さ）。歌詞の出典は ChordWiki。

## 事実の扱い

- コード、キー、BPM、クレジット、スコアの数値は `songs.json` と元の分析から変えない。書き直しは文体と構成の変更で、内容の追加・削除は最小限にする。
- 「カタログ最速」「唯一」「最多」などの最上級は、今の `songs.json` で確かめてから書く。古い曲の記事では「リリース時点では」と時点を明記するか、「〜に次ぐ」と現在の順位で書く。
- 他の曲名は `songs.json` の `title` の表記で書く。
